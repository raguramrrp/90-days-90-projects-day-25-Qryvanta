# QRYVANTA — Dataset Documentation

## Local Synthetic Training Dataset (`data/synthetic/synthetic_support_tickets.csv`)

- **Origin**: Deterministically generated by `data/synthetic/generate_dataset.py` (seed `42`) specifically for local development, reproducible ML benchmarking, and portfolio demonstrations.
- **License**: MIT License (authored within this repository; contains zero real customer data or PII).
- **Important Notice**: Every generated record carries `is_demo_data=True` and `dataset_source='synthetic_demo_v1'`. Synthetic records are never presented as real customer activity.

### Schema

| Column | Type | Description |
|---|---|---|
| `record_id` | string | Unique synthetic identifier (`SYN-0001` .. `SYN-0576`) |
| `template_group_id` | string | Template family ID used by `StratifiedGroupKFold` to prevent phrasing leakage across train/test splits |
| `subject` | string | Support ticket subject line |
| `description` | string | Detailed issue description |
| `category` | string | One of 8 configurable top-level categories |
| `subcategory` | string | One of 24 subcategories (3 per category) |
| `is_demo_data` | boolean | Explicitly `True` |
| `dataset_source` | string | `synthetic_demo_v1` |

### Regenerating the Dataset

```powershell
.\.venv\Scripts\python.exe data\synthetic\generate_dataset.py
```

## Integrating Public Customer Support Datasets

QRYVANTA's training pipeline (`ml/training/train_pipeline.py`) accepts any CSV containing `subject`, `description`, `category`, and optional `subcategory` columns.

Before importing any external public dataset (such as Bitext Customer Support datasets or permissively licensed Kaggle ticket corpora):
1. Verify license permissions and attribution requirements.
2. Inspect actual columns and class balance.
3. Do not fabricate priority, sentiment, or SLA columns if absent from the source dataset.
4. PII anonymization runs automatically during preprocessing (`ml/preprocessing/text_cleaner.py`), though raw files should still be reviewed prior to ingestion.
